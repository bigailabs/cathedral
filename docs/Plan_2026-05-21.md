# Cathedral SAT Launch Readiness Plan - 2026-05-21

This note reviews how `cathedral` implements the reference SAT prototype and whether the current branch is ready to launch SAT on Bittensor.

## Verdict

Not ready for mainnet SAT launch yet.

Cathedral implements the core reference SAT shape: satisfiable DIMACS CNF, solver-style DIMACS answers, deterministic verification, binary scoring, one active formula, and winner-based challenge advancement. It also adds Cathedral/Bittensor plumbing: signed public rows, validator-pulled signed eval rows, local burn policy, hotkey-to-uid mapping, and `set_weights`.

The first-submitted receipt ordering and miner-facing CNF transport mismatches found in the original review have been addressed in this working tree. The remaining launch blockers are conservative mainnet defaults, operator-side mainnet checks, and staging proof that the target publisher/validator deployment behaves correctly under the selected SAT storage mode.

## Implementation Status

Implemented in this working tree:

- First-submitted valid receipt ordering is wired into the SAT runtime path.
- `SshHermesRunner.run_task_family_challenge()` can record a receipt immediately after Hermes stdout returns and before trace collection.
- Publisher startup creates the receipt-store schema.
- SAT docs now describe `cnf_url` transport and first-submitted valid receipt ordering.
- `resign_task_family_score()` has its missing import fixed so delayed loser rows can be re-signed.
- Operator-seeded SAT CNFs now have an explicit launch-size limit via `CATHEDRAL_SYNTHETIC_BOOLEAN_V1_MAX_CNF_BYTES` (default 64 MiB).
- `cathedral-publisher sat-launch-preflight` now validates the SAT launch environment before DB mutation: SAT feed/runtime gates, public base URL, active CNF readability, DIMACS metadata, launch size limit, tier parsing, and the eval-row signing key.
- `cathedral-validator sat-launch-preflight` now validates validator-side SAT launch config before any Bittensor call: placeholder keys, signed eval public key env, and local SAT weight safety.
- `cathedral-validator chain-launch-preflight` now inspects live Bittensor state without submitting `set_weights`: current block, metagraph block/size, validator registration, hotkey-to-uid mapping, validator permit/stake when exposed by the SDK, and selected subnet hyperparameters for weight cadence and commit-reveal/immunity review.
- `parse_dimacs_cnf_metadata_file()` and `verify_dimacs_solution_file()` provide a file-backed DIMACS verification path that streams CNF data from disk without materializing the full formula string.
- `CATHEDRAL_SYNTHETIC_BOOLEAN_V1_STORAGE_MODE=file` now seeds active CNFs as publisher-local file references, serves them through the token-gated CNF endpoint, and verifies submitted solutions through the file-backed verifier path.
- `cathedral sat-active-challenge-status` and `cathedral-publisher sat-active-challenge-status` now report private-safe active SAT challenge metadata, including storage mode, CNF hash, dimensions, file readability, file size, and optional file-hash verification without printing raw CNF, local paths, or fetch tokens.
- `cathedral sat-active-cnf-probe` and `cathedral-publisher sat-active-cnf-probe` now exercise the real token-gated public CNF download path, stream the response, verify the active challenge hash, measure throughput, and fail closed without printing raw CNF, fetch tokens, full URLs, or local paths.

Still not complete for mainnet launch:

- Multi-GB CNF use still needs target-environment staging with file-backed storage plus proxy timeout and throughput checks before production use. The active-challenge status and CNF URL probe commands are available locally, but they still need to be exercised in the target publisher environment.
- Mainnet validator/publisher secrets and running the Bittensor live-chain preflight in target validator environments remain operator tasks.

## Findings

### 1. Resolved: SAT Winner Ordering Is Launch-Consistent

`README.md` says SAT weight must not move above `0.0` until the target branch carries the first-submitted receipt ordering state machine. It also describes the launch rule as first submitted among valid receipts.

The original review found that the active orchestrator path verified first and then awarded the lock to whichever valid result reached `try_lock` first:

- `src/cathedral/eval/orchestrator.py`
- `src/cathedral/lanes/challenge_lock.py`

Current implementation records a durable SAT receipt when Hermes stdout is received, resolves receipts as valid or invalid after verification, waits behind earlier unresolved receipts, and selects the earliest valid receipt before locking/promoting the challenge. The launch docs now describe first-submitted valid receipt ordering consistently.

Residual risk: live publisher and validator environments still need launch preflight runs.

### 2. Resolved: First-Submitted Receipt Support Is Integrated

`src/cathedral/lanes/challenge_receipts.py` defines a publisher-private receipt store and first-submitted selection logic. Tests cover the state machine.

The production path now wires the receipt store into the SAT runtime. `SshHermesRunner.run_task_family_challenge()` accepts a receipt callback and calls it immediately after Hermes stdout returns, before trace collection. The orchestrator finalizes receipt-ordered winners and publishes resolved loser rows.

`src/cathedral/lanes/sign.py` now imports `base64` for `resign_task_family_score()`.

Residual risk: live publisher and validator environments still need launch preflight runs.

### 3. Blocker: Current Mainnet Defaults Intentionally Do Not Launch SAT Emissions

`config/mainnet.toml` still has operational placeholders and disabled SAT weight:

- `validator_hotkey = "REPLACE_ME"`
- `weights.task_family_weights = { synthetic_boolean_v1 = 0.0 }`

Impact: the branch can be staged or shadow-run, but it is not configured to move SAT weight on mainnet until operators intentionally enable local task-family blending.

### 4. Mitigated: Large Formula Handling Has An Opt-In File Path

The reference prototype task notes explicitly anticipate formulas that may take gigabytes or much more memory.

The default `sqlite_text` publisher path still:

- Reads the full operator CNF file into memory at publisher startup.
- Stores the full CNF as SQLite `TEXT`.
- Serves the CNF body from SQLite.
- Verifies using Python strings and repeated `splitlines()` passes.

Relevant files:

- `src/cathedral/publisher/app.py`
- `src/cathedral/lanes/challenge_source.py`
- `src/cathedral/lanes/synthetic_boolean_v1/dimacs.py`

This working tree now also supports `CATHEDRAL_SYNTHETIC_BOOLEAN_V1_STORAGE_MODE=file`: publisher startup validates metadata from the operator CNF path without materializing it, stores a private local path instead of SQLite `TEXT`, serves the CNF through the existing token-gated endpoint as a file response, and verifies submitted solutions by streaming the CNF from disk.

Impact: small first-launch fixtures can keep using the default size-limited `sqlite_text` path. Large DIMACS races should use the file-backed mode, confirm active metadata with `cathedral sat-active-challenge-status --verify-cnf-hash`, probe public download behavior with `cathedral-publisher sat-active-cnf-probe`, and be shadow-run in the target deployment before production weight.

### 5. Resolved: Miner Docs Match Current CNF Transport

The original review found that `docs/miner/QUICKSTART.md` said Hermes receives or reads the CNF from the prompt.

The actual prompt built by `src/cathedral/lanes/publisher.py` sends `public_input.cnf_url` and `public_input.cnf_sha256`, instructing miners to fetch the CNF via HTTP and verify the body hash.

The miner quickstart and launch rails now describe `cnf_url`/`cnf_sha256` transport.

## Prototype Coverage

Implemented relative to the reference SAT prototype:

- DIMACS CNF parsing.
- DIMACS SAT solver output parsing.
- SAT-only scoring with `s SATISFIABLE`.
- Complete-assignment requirement.
- Clause-by-clause verifier.
- Binary score.
- Active challenge source.
- Winner lock and challenge promotion.
- Public-safe hash-only signed rows.
- Validator-side signed eval pull path with local weight computation.

Not fully implemented or not equivalent:

- The reference C++ verifier is not used in the runtime path.
- SHA-256 CNF generator is not integrated.
- UNSAT proof support is intentionally absent.
- Large CNF storage/serving is opt-in file-backed rather than the default path.

## Bittensor Readiness Notes

Before launch, operators still need to verify current live subnet hyperparameters and validator state with:

```bash
cathedral-validator chain-launch-preflight --config config/mainnet.toml
```

The command reports:

- `set_weights` cadence and rate limit.
- Commit-reveal settings.
- Immunity period relative to commit-reveal.
- Validator registration and permit/stake status.
- Hotkey-to-uid mapping on the live metagraph.
- Validator local task-family weight configuration.

Local task-family blending remains off by default. Validators verify publisher-signed eval rows, compute weights locally, and apply local burn policy before `set_weights`.

## Minimum Launch Checklist

Done in this working tree:

1. Decide one SAT winner ordering rule: first submitted among valid receipts.
2. Wire `challenge_receipts.py` into the runtime path before verification and trace collection finalization.
3. Finalize delayed score signing and fix `resign_task_family_score()`.
4. Align `README.md`, `docs/lanes/synthetic-boolean-launch-rails.md`, `docs/miner/QUICKSTART.md`, and `src/cathedral/publisher/skill_md.py`.
5. Add production tests covering two miners where later verification completes first but earlier valid receipt wins.
6. Add receipt-store tests proving unresolved earlier receipts can block and then unblock later valid receipts.
7. Constrain launch CNF size while the runtime uses Python string/SQLite CNF handling.
8. Wire opt-in file-backed CNF storage, token-gated file serving, and file-backed solution verification for large formulas.
9. Add private-safe active challenge status commands for operator checks of active SAT storage, dimensions, file readability, file size, and optional file-hash verification.
10. Add private-safe active CNF URL probe commands for target proxy download, hash, and throughput checks.
11. Add read-only validator chain launch preflight for registration, permit/stake, live metagraph mapping, and subnet hyperparameter checks.

Remaining before mainnet weight:

1. Run `cathedral-publisher sat-launch-preflight` in the target publisher environment.
2. Run `cathedral-validator sat-launch-preflight` in every target validator environment.
3. Run `cathedral-validator chain-launch-preflight` in every target validator environment.
4. Shadow-run on testnet with `synthetic_boolean_v1 = 0.0`.
5. Enable a small nonzero SAT weight only after validator logs confirm coherent local scoring, burn, and `set_weights`.
6. Shadow-run `CATHEDRAL_SYNTHETIC_BOOLEAN_V1_STORAGE_MODE=file` in the target publisher environment and capture `sat-active-challenge-status --verify-cnf-hash` plus `sat-active-cnf-probe` output before seeding multi-GB formulas.
