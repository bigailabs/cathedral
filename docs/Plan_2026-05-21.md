# Cathedral SAT Launch Readiness Plan - 2026-05-21

This note reviews how `cathedral` implements the `fred-bsat` prototype and whether the current branch is ready to launch SAT on Bittensor.

## Verdict

Not ready for mainnet SAT launch yet.

Cathedral implements the core `fred-bsat` shape: satisfiable DIMACS CNF, solver-style DIMACS answers, deterministic verification, binary scoring, one active formula, and winner-based challenge advancement. It also adds Cathedral/Bittensor plumbing: signed public rows, validator-pulled signed weight vectors, burn policy, hotkey-to-uid mapping, and `set_weights`.

The first-submitted receipt ordering and miner-facing CNF transport mismatches found in the original review have been addressed in this working tree. The remaining launch blockers are conservative mainnet defaults, large-formula scalability beyond the explicit first-launch size limit, unavailable full pytest verification in this environment, and operator-side mainnet checks.

## Implementation Status

Implemented in this working tree:

- First-submitted valid receipt ordering is wired into the SAT runtime path.
- `SshHermesRunner.run_task_family_challenge()` can record a receipt immediately after Hermes stdout returns and before trace collection.
- Publisher startup creates the receipt-store schema.
- SAT docs now describe `cnf_url` transport and first-submitted valid receipt ordering.
- `resign_task_family_score()` has its missing import fixed so delayed loser rows can be re-signed.
- Operator-seeded SAT CNFs now have an explicit launch-size limit via `CATHEDRAL_SYNTHETIC_BOOLEAN_V1_MAX_CNF_BYTES` (default 64 MiB).
- `cathedral-publisher sat-launch-preflight` now validates the SAT launch environment before DB mutation: active CNF readability, DIMACS metadata, launch size limit, tier parsing, and required signing keys.
- `cathedral-validator sat-launch-preflight` now validates validator-side SAT launch config before any Bittensor call: placeholder keys, signed eval public key env, remote-weight opt-in, pinned remote-weight key env, and local SAT weight safety.
- `cathedral-validator verify-remote-weight-vector` now fetches and verifies the publisher's signed remote weight vector before any live metagraph mapping or `set_weights` call.

Still not complete for mainnet launch:

- Full pytest has not run in this environment.
- Large multi-GB CNF handling still needs a file-backed/native verifier path before production use; current launch is explicitly size-limited.
- Mainnet validator/publisher secrets, remote-weight opt-in, and Bittensor live hyperparameter checks remain operator tasks.

## Findings

### 1. Resolved: SAT Winner Ordering Is Launch-Consistent

`README.md` says SAT weight must not move above `0.0` until the target branch carries the first-submitted receipt ordering state machine. It also describes the launch rule as first submitted among valid receipts.

The original review found that the active orchestrator path verified first and then awarded the lock to whichever valid result reached `try_lock` first:

- `src/cathedral/eval/orchestrator.py`
- `src/cathedral/lanes/challenge_lock.py`

Current implementation records a durable SAT receipt when Hermes stdout is received, resolves receipts as valid or invalid after verification, waits behind earlier unresolved receipts, and selects the earliest valid receipt before locking/promoting the challenge. The launch docs now describe first-submitted valid receipt ordering consistently.

Residual risk: full pytest still needs to run in an environment with project dependencies installed.

### 2. Resolved: First-Submitted Receipt Support Is Integrated

`src/cathedral/lanes/challenge_receipts.py` defines a publisher-private receipt store and first-submitted selection logic. Tests cover the state machine.

The production path now wires the receipt store into the SAT runtime. `SshHermesRunner.run_task_family_challenge()` accepts a receipt callback and calls it immediately after Hermes stdout returns, before trace collection. The orchestrator finalizes receipt-ordered winners and publishes resolved loser rows.

`src/cathedral/lanes/sign.py` now imports `base64` for `resign_task_family_score()`.

Residual risk: the receipt path should still be covered by full pytest before launch.

### 3. Blocker: Current Mainnet Defaults Intentionally Do Not Launch SAT Emissions

`config/mainnet.toml` still has operational placeholders and disabled SAT weight:

- `validator_hotkey = "REPLACE_ME"`
- `weights.task_family_weights = { synthetic_boolean_v1 = 0.0 }`
- `[remote_weight_source].enabled = false`

Publisher signed weight production also requires `CATHEDRAL_WEIGHT_POLICY_SIGNING_KEY`; without it, startup logs `weight_policy_signing_key_missing` and `/v1/validator/weights/next` has no useful vector.

Impact: the branch can be staged or shadow-run, but it is not configured to move SAT weight on mainnet.

### 4. High: Large BSAT Formula Handling Is Not Production-Scale

`fred-bsat/docs/task_2026-05-18.md` explicitly anticipates formulas that may take gigabytes or much more memory.

Cathedral currently:

- Reads the full operator CNF file into memory at publisher startup.
- Stores the full CNF as SQLite `TEXT`.
- Serves the CNF body from SQLite.
- Verifies using Python strings and repeated `splitlines()` passes.

Relevant files:

- `src/cathedral/publisher/app.py`
- `src/cathedral/lanes/challenge_source.py`
- `src/cathedral/lanes/synthetic_boolean_v1/dimacs.py`

The parser is streaming in assignment representation, but not in CNF storage or text traversal. It is acceptable for small launch fixtures and readiness probes, not for serious large DIMACS races.

Impact: first launch must constrain formula size, or move CNF storage/verification to a file-backed or native verifier path. This working tree now implements the conservative launch constraint.

### 5. Resolved: Miner Docs Match Current CNF Transport

The original review found that `docs/miner/QUICKSTART.md` said Hermes receives or reads the CNF from the prompt.

The actual prompt built by `src/cathedral/lanes/publisher.py` sends `public_input.cnf_url` and `public_input.cnf_sha256`, instructing miners to fetch the CNF via HTTP and verify the body hash.

The miner quickstart and launch rails now describe `cnf_url`/`cnf_sha256` transport.

## Prototype Coverage

Implemented relative to `fred-bsat`:

- DIMACS CNF parsing.
- DIMACS SAT solver output parsing.
- SAT-only scoring with `s SATISFIABLE`.
- Complete-assignment requirement.
- Clause-by-clause verifier.
- Binary score.
- Active challenge source.
- Winner lock and challenge promotion.
- Public-safe hash-only signed rows.
- Validator-side signed-weight relay path.

Not fully implemented or not equivalent:

- `fred-bsat` C++ verifier is not used in the runtime path.
- SHA-256 CNF generator is not integrated.
- UNSAT proof support is intentionally absent.
- Large CNF file handling is not ready for multi-GB formulas.

## Bittensor Readiness Notes

Before launch, operators still need to verify current live subnet hyperparameters and validator state:

- `set_weights` cadence and rate limit.
- Commit-reveal settings.
- Immunity period relative to commit-reveal.
- Validator registration and permit/stake status.
- Hotkey-to-uid mapping on the live metagraph.
- Pinned weight-policy public key on every validator using remote weights.

Remote signed weights are the safer launch path because validators verify a publisher-signed vector before applying it. Local task-family blending remains off by default.

## Minimum Launch Checklist

Done in this working tree:

1. Decide one SAT winner ordering rule: first submitted among valid receipts.
2. Wire `challenge_receipts.py` into the runtime path before verification and trace collection finalization.
3. Finalize delayed score signing and fix `resign_task_family_score()`.
4. Align `README.md`, `docs/lanes/synthetic-boolean-launch-rails.md`, `docs/miner/QUICKSTART.md`, and `src/cathedral/publisher/skill_md.py`.
5. Add production tests covering two miners where later verification completes first but earlier valid receipt wins.
6. Add receipt-store tests proving unresolved earlier receipts can block and then unblock later valid receipts.
7. Constrain launch CNF size while the runtime uses Python string/SQLite CNF handling.

Remaining before mainnet weight:

1. Run `cathedral-publisher sat-launch-preflight` in the target publisher environment.
2. Run `cathedral-validator sat-launch-preflight` in every target validator environment.
3. Run full pytest in Python 3.11 or 3.12.
4. Shadow-run on testnet with `synthetic_boolean_v1 = 0.0`.
5. Produce signed remote weight vectors in staging and verify them with `cathedral-validator verify-remote-weight-vector`.
6. Enable a small nonzero SAT weight only after validator remote opt-in and logs confirm coherent `set_weights`.
7. Implement a file-backed/native verifier path before seeding multi-GB formulas.
